Data Syncronization Standard: v1.2 - Sales Integration

This documentation establishes the technical standard for hotel chains or partners to provide reservation data to the TravelCash cashback processing engine, providing a data sample model needed by Units for the integration with our services.

Business Rules (Cashback Logic)

The TravelCash system applies cashback and subsidy percentages based on Source and Campaign triggers. Below is an example of the current rule structure:

Rule Example: Direct
Source Trigger: "Own Website", "Reservation Center", "Engine X"
Campaign Trigger: "SUMMER2026"
Result: [X]% Cashback | [Y]% Partner Subsidy

Unit Mapping

If the endpoint is centralized for the entire chain, the hotel identifier field must allow internal mapping. The partner must list the available units:

Unit Name (Display) ID/Slug for Integration
[Example Unit 01]unit_01_slug
[Example Unit 02]unit_02_slug

Endpoint Request

TravelCash will consume a REST API via the GET method for periodic synchronization.

GET /api/[sync_route]

Required Filter Parameters:

  • Start Date: Start filter based on checkout date.
  • End Date: End filter based on checkout date.

Data Model Requirements (JSON)

Although property names may vary according to the partner's API, the data below is mandatory for cashback processing:

Required Field Type Req. System Role
Reservation IDStringYesUnique identifier to prevent duplication.
Hotel IDStringYesIdentifies which chain unit generated the reservation.
Checkout DateDateYesCheckout date (balance release trigger).
Base AmountDecimalYesNet amount over which the % will be applied.
SourceStringYesValidates whether the reservation is eligible (e.g. Website vs OTA).
CampaignStringYesDefines the applied business rule.
Customer NameStringYesHolder identification.
Customer EmailStringYesPrimary Key for TravelCash crediting.

Padrão de Integração de Dados: v1.2 - Integração de Vendas

Esta documentação estabelece o padrão técnico para que redes hoteleiras ou parceiros disponibilizem dados de reservas para o motor de processamento de cashback da TravelCash, servindo como exemplo modelo de dados que as unidades precisarão exportar.

Regras de Negócio (Lógica de Cashback)

O sistema TravelCash aplica porcentagens de cashback e subsídio baseando-se em gatilhos de Origem e Campanha. Abaixo, o exemplo da estrutura de regras vigente:

Exemplo de Regra: Direta
Gatilho Origem: "Site Próprio", "Central de Reservas", "Motor X"
Gatilho Campanha: "VERAO2026"
Resultado: [X]% Cashback | [Y]% Subsídio Parceiro

Mapeamento de Unidades (De-Para)

Se o endpoint for centralizado para toda a rede, o campo identificador do hotel deve permitir o mapeamento interno. O parceiro deve listar as unidades disponíveis:

Nome da Unidade (Exibição) ID/Slug para Integração
[Unidade Exemplo 01]unidade_01_slug
[Unidade Exemplo 02]unidade_02_slug

Solicitação de Endpoint

A TravelCash consumirá uma API REST via método GET para sincronização periódica.

GET /api/[rota_de_sincronia]

Parâmetros Obrigatórios para Filtro:

  • Data Inicial: Filtro de início baseado na data de checkout.
  • Data Final: Filtro de fim baseado na data de checkout.

Requisitos do Modelo de Dados (JSON)

Embora os nomes das propriedades possam variar conforme a API do parceiro, os dados abaixo são mandatórios para o lançamento do cashback:

Campo Requerido Tipo Obrig. Função no Sistema
ID ReservaStringSimIdentificador único para evitar duplicidade.
ID HotelStringSimIdentifica qual unidade da rede gerou a reserva.
Data SaídaDateSimData de checkout (Gatilho de liberação do saldo).
Valor BaseDecimalSimValor líquido sobre o qual o % incidirá.
OrigemStringSimValida se a reserva é elegível (Ex: Site vs OTA).
CampanhaStringSimDefine a regra de negócio aplicada.
Nome ClienteStringSimIdentificação do titular.
Email ClienteStringSimChave Primária para crédito da TravelCash.
