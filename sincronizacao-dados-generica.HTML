Integração de Reservas: [NOME_DO_PARCEIRO] v1.2 - Generic

Esta documentação estabelece o padrão técnico para que redes hoteleiras ou parceiros disponibilizem dados de reservas para o motor de processamento de cashback da TravelCash.

Regras de Negócio (Lógica de Cashback)

O sistema TravelCash aplica porcentagens de cashback e subsídio baseando-se em gatilhos de Origem e Campanha. Abaixo, o exemplo da estrutura de regras vigente:

Exemplo de Regra: Direta
Gatilho Origem: "Site Próprio", "Central de Reservas", "Motor X"
Gatilho Campanha: "VERAO2026"
Resultado: [X]% Cashback | [Y]% Subsídio Parceiro

Mapeamento de Unidades (De-Para)

Se o endpoint for centralizado para toda a rede, o campo identificador do hotel deve permitir o mapeamento interno. O parceiro deve listar as unidades disponíveis:

Nome da Unidade (Exibição) ID/Slug para Integração
[Unidade Exemplo 01]unidade_01_slug
[Unidade Exemplo 02]unidade_02_slug

Solicitação de Endpoint

A TravelCash consumirá uma API REST via método GET para sincronização periódica.

GET /api/[rota_de_sincronia]

Parâmetros Obrigatórios para Filtro:

  • Data Inicial: Filtro de início baseado na data de checkout.
  • Data Final: Filtro de fim baseado na data de checkout.

Requisitos do Modelo de Dados (JSON)

Embora os nomes das propriedades possam variar conforme a API do parceiro, os dados abaixo são mandatórios para o lançamento do cashback:

Campo Requerido Tipo Obrig. Função no Sistema
ID ReservaStringSimIdentificador único para evitar duplicidade.
ID HotelStringSimIdentifica qual unidade da rede gerou a reserva.
Data SaídaDateSimData de checkout (Gatilho de liberação do saldo).
Valor BaseDecimalSimValor líquido sobre o qual o % incidirá.
OrigemStringSimValida se a reserva é elegível (Ex: Site vs OTA).
CampanhaStringSimDefine a regra de negócio aplicada.
Nome ClienteStringSimIdentificação do titular.
Email ClienteStringSimChave Primária para crédito da TravelCash.
