Integração de Vendas MME v4.2

Este documento orienta o desenvolvimento da OCL para o envio automático de vendas para a TravelCash. Os dados enviados alimentarão o ecossistema de cashback para os hóspedes do grupo MME.

Evolução Tecnológica MME

Esta nova etapa da parceria entre MME e TravelCash visa modernizar o tráfego de dados, substituindo o processamento baseado em arquivos por uma arquitetura orientada a eventos via API.

Cenário Atual (SFTP/Blob)

Os dados são exportados em arquivos para um servidor SFTP (Azure Blobs), onde um sincronizador realiza a leitura periódica.

  • Dependência de leitura de arquivos físicos.
  • Delay entre a exportação e o processamento.
  • Dificuldade de rastreio de erros pontuais.

Cenário Desejado (API Rest)

A OCL envia os dados diretamente para a API TravelCash, que insere as informações instantaneamente na fila de processamento.

  • Performance: Processamento em tempo real (Near Real-Time).
  • Segurança: Tráfego criptografado via HTTPS e chaves de cliente individuais.
  • Integridade: Validação imediata dos dados no ato do envio.

Unidades MME Habilitadas

O sistema OCL deve identificar a qual unidade a reserva pertence e utilizar o x-client-key correspondente:

  • MME - Maceio Resort

Autenticação

A API utiliza autenticação por chave de cliente no Header:

x-client-key: <CHAVE_ESPECIFICA_DA_UNIDADE>
Content-Type: application/json

Mapeamento de Dados (OCL → TravelCash)

Abaixo, como os campos enviados pela OCL devem ser mapeados para a nossa API:

Campo APICampo MME (CSV/OCL)Descrição
valuediaria_totalValor bruto da venda (Ex: 1185.00)
identificatornumeroID único da reserva/venda.
userNameNome SolicitanteNome completo do hóspede.
userMailemail_solicitanteE-mail para crédito do cashback.
userPhoneTelefone SolicitanteTelefone com DDD.
checkoutTimedata_saidaData do checkout (ISO 8601).

Campos em extraData: Segmento, Código Tarifa, Data Chegada, Origem e CampanhaTC devem ser enviados dentro do objeto JSON extraData.
